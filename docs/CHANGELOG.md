## Changelog Guidelines

- Add entries when meaningful changes are made.
- Group entries under `Added`, `Changed`, `Fixed`, `Removed`, or `Security`.
- Write entries in concise, user-understandable language.
- Record completed changes rather than future plans.
- Do not describe a feature as implemented until it exists and has been verified.
- Keep the newest entries at the top.
- Use release dates only when a release is actually created.
- Reference relevant task IDs or commit hashes when useful.
- Avoid listing every minor code edit or formatting-only change.
